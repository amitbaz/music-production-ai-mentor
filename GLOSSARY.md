# Glossary

- **Mentor** — the product: a music production mentor the user talks to. It explains when asked to explain, and acts through its tools when asked to act, saying why. Its tool sets are what it can act through, not what it is.
- **App** — one way the user reaches the mentor, such as the terminal or a desktop window. It owns what the user sees and keeps the conversation; the mentor is the same in every app.
- **Agent** — a model, a system prompt and a set of tools, joined by the harness. Given a conversation and the user's text it runs one turn. It keeps nothing between turns. The mentor is an agent with those three chosen.
- **Agent loop** — the cycle at the centre of the harness: send the conversation to the model; if the reply asks for tool calls, run them, append the results, and send again; stop when the model replies with text only (or the round limit is hit).
- **Harness** — everything around the model that makes it an agent: the agent loop, the tools, the conversation, and the provider adapters.
- **Conversation** — the ordered list of messages the harness keeps and re-sends on every model call, from the latest summary on. The model has no memory; the conversation is the memory. Messages before the latest summary stay in the conversation for the app, but the model no longer sees them.
- **Message** — one entry in the conversation, in our own neutral format. Five kinds: user text, assistant text, tool call, tool result, summary.
- **Summary** — a message that stands in for the older part of the conversation, written by the model when the conversation grows past the summary threshold. It is history, not something the user said.
- **Summary threshold** — the conversation size at which the harness summarises, the same for every model. It is set for cost and answer quality, far below any supported model's context window.
- **System prompt** — standing instructions for the model: who it is and how to behave. It is sent with every model call, next to the conversation and the tools, and is never a message in the conversation.
- **Provider meta** — an optional slot on a model-produced message where a provider adapter stores provider-specific values (e.g. Gemini's `thoughtSignature`, Claude's thinking blocks), tagged with the provider that wrote it. The agent loop carries it without reading it, and an adapter reads only what it wrote itself.
- **Provider** — a company's model API (Gemini, Anthropic, …).
- **Model** — one model at one provider, as the agent loop sees it: the thing a model call is made on.
- **Provider adapter** — the one module that knows a provider's HTTP API. It translates the conversation into that provider's request and the reply back, and gives the harness its models. The agent loop never sees provider-specific shapes.
- **Model id** — the string that names a model and the provider that serves it, written `provider:model`, such as `gemini:gemini-3.5-flash-lite`. The part after the first colon is the name the provider itself uses.
- **Context window** — the most tokens a model can take in one model call: the conversation, the system prompt and the tools together.
- **Supported model** — a model on the harness's fixed list, each shown by its provider's documentation to have a context window of at least 1,000,000 tokens. A model id not on the list is refused.
- **Provider lookup** — the part of the harness that gives the model for a model id, by finding the provider adapter the id names.
- **Scripted model** — a fake model that returns canned replies, used to test the agent loop without a network.
- **Tool** — a named function the model can ask the harness to run, described to the model by a name, a description and an argument schema.
- **Tool set** — a group of tools for one sense of the mentor on one outside source: what Live's API gives, what Live sounds like, what Live shows. The mentor is given one or more tool sets.
- **Eyes** — the mentor seeing Live's own windows, its main window and its plug-in windows, as pictures. Never another app or the whole screen.
- **Hands** — the mentor working a real mouse and keyboard in Live's windows, for what the API cannot reach. Anything the API can do stays with the API.
- **Look** — one picture of one of Live's windows, or of a part of it, taken for the model. A hand action is aimed at the last look of its window.
- **DAW** — a digital audio workstation, the application music is produced in. Ableton Live is the first one supported.
- **Tool call** — the model's request to run a tool with given arguments.
- **Tool result** — what the harness sends back after running a tool call, including errors. It is text, and may carry media.
- **Media** — a picture or a sound inside a tool result, sent to the model as the provider takes it, with its own token estimate.
- **Result limit** — the most characters one tool result may hold. Past it, the harness keeps the start and adds a note saying how much was cut. A tool whose answer grows with the Live Set keeps itself under the limit, so the cut is only a safety net.
- **Conversation size** — how many tokens the conversation takes when sent to the model, as best the harness knows: the count the provider gave on the last model call, plus an estimate for what was added since. Reported with each turn's result.
- **Characters per token** — how many characters of text one token takes for a supported model, used to estimate the size of text no provider has counted yet. Each supported model has its own number. Today each is an estimate, not a measurement, and a model that gives none is taken as four.
- **Live Set** — the project open in Ableton Live: its tracks, devices, clips and settings, whether saved to a file or not.
- **Remote Script** — code that runs inside Ableton Live and lets an outside program read and change the Live Set. The Ableton tools reach Live through one.
- **Pairing a DAW** — the one-time step on a computer that lets the mentor reach a DAW: for Ableton Live, installing the mentor's Remote Script and creating the password it is reached with. Unpairing undoes it. Pairing is not connecting: once a DAW is paired, the client connects to it whenever it is open. The mentor can be talked to whether a DAW is paired or not.
- **Client** — the part of a tool set that talks to an outside program for its tools, such as the one that connects to the Remote Script in Live. The Ableton client connects when a tool first needs it and gives out the object ids; the knowledge base's connects when the mentor starts.
- **Knowledge base** — what a good producer knows, such as how to mix, arrange or design a sound, kept as notes in a private repo and searched by the mentor through its tools. It is optional: without it the mentor works from its system prompt and its model alone. How the mentor works in Live belongs in the system prompt, not here.
- **Diagnosis** — what the mentor establishes before it changes anything: the fault, where in the Live Set it can be fixed, and the evidence for both. Like a producer handed someone else's Set, it cannot know which control was moved, only what it hears and reads. A fix is right when the sound comes back with nothing else changed, so two fixes that sound the same are both right, such as a synth's transpose or a Pitch device in front of it. When the patch makes that uncertain, such as several oscillators or key-tracked envelopes, the mentor gathers more evidence before it chooses.
- **MCP server** — a program that offers tools over the Model Context Protocol. The knowledge base is reached through one; the harness lists its tools when it connects and passes them to the model as they are.
- **Arrangement View** — the timeline of a Live Set, where clips are laid out from left to right to form the finished piece. The other view, Session View, is a grid of clips launched by hand.
- **Locator** — a named marker on the timeline of the Arrangement View, such as "Drop". Live's own word is cue point.
- **Native device** — an instrument or effect that is part of Ableton Live, such as EQ Eight or Compressor. A third-party plug-in is not one.
- **Third-party plug-in** — an instrument or effect from another maker that Live hosts, such as FabFilter Pro-C 2. It comes in a plug-in format, VST3, AU or VST2, and the same plug-in is often installed in more than one; the mentor prefers VST3, then AU, then VST2. It is a device, but not a native device.
- **Configure list** — the parameters of one third-party plug-in that Live shows in its device panel and to a script, at most 128: all of them for a plug-in with 64 or fewer, otherwise only those the user added with Configure. A setting outside it is reached only in the plug-in's own window.
- **Browser item** — a device, preset, kit or sample in Live's browser. It is named by its browser path: the folders from the browser's top level down to it, then its own name, such as `drums/Kit-Core 808.adg`. Unlike an object id, a browser path lasts across connections.
- **Loading** — putting a browser item onto a track or rack chain as a device, as Live does when one is dragged from the browser: a preset or kit becomes its device, and a sample becomes a Simpler. Placing a sample on the timeline as a clip is not loading.
- **Placing a sample** — putting an audio file from disk onto an audio track's timeline in the Arrangement View, as a clip that starts at a bar and is as long as the file. It is not loading: no device is added.
- **Rack chain** — one of the parallel signal paths inside a rack device, such as an Audio Effect Rack, each with its own devices in order. A rack can hold racks.
- **Object id** — a short name such as `t17`, `d204`, `c3`, `ch2`, `n12` or `l2` that a read gives to a track, device, clip, rack chain, note or locator, and that a later tool call uses to say which one it means. It follows the object through renames and reorders, and lasts as long as the connection to Live.
- **Round** — one model call plus the tool calls it triggers. The agent loop is capped at 10 rounds per turn.
- **Model call** — asking the model once for its next reply, as the agent loop sees it. One per round; made of one or more attempts.
- **Reply** — what a model call returns: the new messages, the token count the provider reported for the call if it gave one (the whole request plus the reply, cached tokens included), and whether the reply was cut off by the output limit.
- **Attempt** — one request sent to the provider.
- **Retryable failure** — a failed attempt that the provider adapter marks as likely to pass if tried again, such as an overloaded provider or a dropped connection.
- **Retry** — a further attempt after a retryable failure, made after a wait that grows each time. An attempt whose reply has started to arrive is never retried. A model call fails when a failure is not retryable or the retries run out.
- **Timeout** — an attempt stopped because no text arrived from the model for the length of its time limit. It is a retryable failure, and is not a cancel.
- **Turn** — everything the agent loop does in answer to one user message: one or more rounds, ending with a stop reason.
- **Update** — something the agent reports to the app while a turn runs: a piece of assistant text that has just arrived, a whole message, or a notice that summarising has started, or that it failed and the turn carries on. Every message added to the conversation is reported as one update.
- **Streaming** — the app receiving assistant text in pieces while the model is still writing it, each piece as an update, before the whole message. The app turns it on or off for each turn; off, it receives whole messages only. Tool calls are never streamed.
- **Stop reason** — why a turn ended: the model finished, the model replied with nothing, the model's reply was cut off by its output limit, the round limit was hit, a model call failed, the model refused, or the user cancelled. It is reported next to the conversation, never as a message inside it.
- **Refused** — a turn ended because the model declined the request on safety grounds, with the category it gave. What arrived before stays in the conversation. It is not a failed model call and is not retried.
- **Cancel** — the user stopping a turn before it ends. What already happened stays in the conversation, including the text of a reply the model was still writing; a tool that is running finishes, and tool calls that had not started get a tool result saying so.
- **Approval** — the user's yes or no to one tool call, asked before it runs. Only tools marked as needing approval are asked about. A refusal becomes the tool result, and the turn continues.
- **Eval** — a check of what the model decides, such as which tool it picks or whether it follows the system prompt. It calls the real model, so it runs on demand and never in `pnpm test`, and its result is a rate over several runs, not a yes or no. A scripted model cannot stand in for the model here, because the decision is the thing being checked.
- **Case** — one eval: a plant and a user message. The runner applies the plant, gives the mentor the message, and grades what the Live Set looks like afterwards.
- **Run** — one execution of a case, from plant to verdict. A case is run several times and reported as how many runs passed.
- **Series** — a case run several times on one model, in one go, reported as runs passed out of runs made.
- **Sandbox** — a throwaway virtual Mac where a series runs, so the user's own Live is never touched. It holds Ableton Live, paired, and opens the base Set fresh before every run. It is deleted after the series, or kept for a look when it gets stuck.
- **Sandbox image** — the prepared virtual Mac every sandbox is copied from: macOS with Live installed, authorized and paired. It never leaves the computer it was made on, because it holds a Live licence.
- **Panel** — the supported models a case is run on. A change is kept when it lifts the panel, not one model; a case low on one model is a model problem, low on all a product problem.
- **Base Set** — a Live Set with no faults, made and mixed by a person, that plants are applied to. Patience is the first. It is never built through the tools and never saved over.
- **Plant** — one known change to a base Set that creates one fault, named so it can be applied and reverted. A plant is made through the tools and is never saved.
- **Answer key** — the plant's before values: what the Live Set looks like with the fault fixed. It is the difference between the base Set and the planted copy, so nobody has to decide what a good mix is; the base Set already is one. For a judgment plant the answer key is a range around each before value.
- **Judgment plant** — a plant whose fix has no single right value, such as a level: a producer sets it by ear, against the standard of the genre. A run fixes it by landing within a range around the before value, and the range is how far apart good engineers set the same element. A plant with one fix, such as a muted track, is not one.
